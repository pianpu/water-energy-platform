# 水电表业务平台原型

双击本目录的 `index.html` 打开，默认进入房间管理，无需安装Java或数据库。建议使用Chrome或Edge。页面均使用本地资源，无CDN依赖。

## 当前已确认范围

- 房间按提供的安装对照表展示：南苑1,622条、紫园396条，共2,018条；只参考项目、幢号、单元、楼层和房号，水电表只关联设备。
- 第三方应用仅设备查询、用电量查询、用水量查询，不提供抄表、通断电或任务接口。
- 告警仅设备离线、设备采集缺失/失败。不设置倍率功能、待确认倍率卡片或倍率确认状态；参与汇总直接统计水表数量。
- 告警状态仅待处理、已确认；列表和详情显示确认人，确认时自动保存当前操作人和确认时间。待处理显示“—”，缺失的历史确认人显示“历史未记录”。
- 采集计划没有范围选择，电表计划默认全部电表，水表计划默认全部水表。
- 电表每半小时采集一次，水表每天00:00采集一次。失败后最多再重试3次（含首次最多4次尝试），默认间隔10秒，可修改。
- 日用水量 = 当日24:00累计读数 − 当日00:00累计读数。日末读数与下一天日初共用一次采集，用水明细仅展示00:00、24:00两个边界读数。
- 峰时08:00–21:00，谷时00:00–08:00、21:00–24:00，不含平时档。

## 推荐体验

1. 在房间管理按南苑/紫园、幢号、单元筛选。查看房间位置与水电表设备关联。
2. 编辑房间，搜索演示设备并关联。不同单元可以有同一房号；同幢同单元同楼层不得重复。设备编码始终保持不变，台账第一列只展示编码；关联后在安装位置/关联房间处显示房间，解绑恢复未关联状态。自身名称在详情和编辑中维护，不被房间覆盖。
3. 采集计划中编辑重试间隔，再点击模拟执行。原型仅有2台设备，电表、水表各1台；每种计划采集对应的1台设备。历史记录包含重试成功和重试耗尽示例。
4. 采集与控制记录按设备类型和操作类型筛选电表/水表抄表。详情逐次展示首次及重试的请求HEX、响应HEX、发送/响应/成功时间（毫秒）；失败不填成功时间，旧日志缺失明确标注。间隔按实际秒数等待；首次加3次重试最多4次尝试。
5. 在用量统计中查看电表 `202607310749`：缺10:30边界点影响相邻两个区间，但日峰谷边界完整仍可统计。
6. 新增第三方应用，确认只有三类查询权限；appSecret在列表和配置中持续完整显示，刷新后仍可查看。查看接口说明，只有设备和用量查询。
7. 台账详情可演示后台手动抄表和电表通断电。通断电需要确认并核验，不自动重试，也不向第三方开放。

## 数据说明

- Excel只读导入，原表未修改。源数据在 `room-template.js`，可离线打开。
- 不展示门锁要求、水电表安装要求或完成情况。原表没有设备编号，水电表初始关联留空，通过编辑房间选择设备关联。
- 原表没有面积、租户、入住状态，初始留空或“未登记”，可作为补充资料填写。
- 原型初始仅提供2台演示设备：电表编码202607310749、水表编码23030016032620。台账第一列仅显示设备编码，不拼接名称、设备类型或房间；设备默认不关联房间，位置在显式关联后展示。连接和读数仍为模拟数据。
- 业务数据保存在 `meter-business-prototype-two-devices-v3`，房间保存在 `meter-business-prototype-rooms-two-devices-v3`。旧原型数据命名空间不修改、不直接混入新模板。
- 更换浏览器或文件/HTTP地址可能使用不同存储；请固定同一入口。浏览器禁用存储或空间不足会提示保存失败。
- 计划不后台自动调度。模拟任务在浏览器内推进；刷新后依已保存时间继续演示。
- 不请求采集地址，不连接设备，不提供真实认证/开放接口。不要输入生产凭证，原型只保存本地演示appSecret以持续显示，不要填写生产凭证。

## 可选HTTP预览

在本目录运行：

```powershell
python -m http.server 18765 --bind 127.0.0.1
```

访问 [本地原型](http://127.0.0.1:18765/)。结束时在启动终端按Ctrl+C停止。文件方式和HTTP方式都是本地交互，数据存储空间可能不同。

详细范围见[需求确认](需求确认.md)。开发方案已按当前确认范围同步，拟新增接口及数据库仍须正式实现。
